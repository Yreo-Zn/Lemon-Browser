## 🎯 Key Concepts

### The 7 Petreas (Inviolable Guardrails)
These **cannot** be changed, removed, or circumvented:

1. **Context Isolation** — Lemon operates in a sandboxed environment
2. **IPC Whitelist** — Only documented inter-process communication allowed
3. **Content Security Policy** — Strict resource loading restrictions
4. **Credential Encryption** — Secrets are always encrypted, never stored plain-text
5. **Extension Security** — All extensions pre-approved, signed, and audited
6. **Process Integrity** — Lemon's processes are continuously monitored
7. **Network Isolation** — All network traffic is inspected and logged

→ **Read more:** [LEMON_CONSTITUTION](governance/03-LEMON_CONSTITUTION.md)

---

### The 3 Autonomy Zones
- **🟢 GREEN** — Lemon can act autonomously (always allowed)
- **🟡 YELLOW** — Requires escalation to Ayatana (reasoning + approval)
- **🔴 RED** — Requires user confirmation (user has final say)

→ **Read more:** [SCOPE](governance/02-SCOPE.md)

---

### The 7 Heartbeat Cycles
Lemon continuously monitors itself at different timescales:

| Cycle | Interval | Purpose |
|-------|----------|---------|
| 🚦 IMMEDIATE | < 1 sec | Real-time reactions |
| ⏰ HOURLY | 1 hour | Checkpoints |
| 📆 DAILY | 24h | Health check & cleanup |
| 📊 WEEKLY | 7d | Governance review |
| 🔍 MONTHLY | 30d | Deep audit |
| 📈 QUARTERLY | 90d | Strategic reflection |
| 🎂 YEARLY | 365d | Full renewal & generation update |

→ **Read more:** [HEARTBEAT](vitality/HEARTBEAT.md)

---

### The 4 Skill Acquisition Pathways
Lemon can acquire new capabilities from:

1. **Ayatana** (recommended) — Curated skills designed by reasoning layer
2. **Swarm KG** — Shared knowledge graph of federated agents
3. **User Feedback** — Skills proposed by user needs
4. **Self-Proposal** — Lemon's own suggestions (with constraints)

→ **Read more:** [SKILL_DYNAMICS](dynamics/06-SKILL_DYNAMICS.md)

### The 3 Types of Change Proposals
Lemon can propose three types of changes to itself:

- **Type A** — Operational improvements (auto-approved)
- **Type B** — Capability expansion (requires user + OCP approval)
- **Type C** — Emergency adaptation (real-time, auditable, user-vetoed)

→ **Read more:** [EVOLUTIONARY_CONSTITUTION](dynamics/07-EVOLUTIONARY_CONSTITUTION.md)

## 🔒 Trust Model

### Trust Passport Levels
- 🥉 **BRONZE** — New relationship, minimal autonomy
- 🥈 **SILVER** — Established trust, expanded green zone
- 🥇 **GOLD** — Full trust (within petreas), advanced features enabled

Your trust level determines Lemon's autonomy. It increases through **demonstrated reliability** and can decrease through **violations or user override**.

### Audit Trail
**Every action Lemon takes is logged immutably.** This is non-negotiable (PETREA #1). You can:
- Review logs at any time
- Verify Lemon's reasoning
- Challenge decisions
- Request rollback of consequences

## ⚖️ The Constitutional Paradox

This constitution is designed to solve a fundamental paradox:

> **How can Lemon be autonomous enough to be useful, yet constrained enough to be safe?**

The answer is **layered trust with escalation thresholds**:

- **Local** (green zone) → Lemon acts autonomously
- **Medium** (yellow zone) → Lemon seeks Ayatana's counsel
- **Critical** (red zone) → User has final say
- **Exceptional** (emergency) → HOTL (Human-On-The-Loop) with opt-out

This model allows Lemon to be **smart, quick, and responsive** without ever violating **user sovereignty**.

## ✨ Key Insight

This constitution was designed to answer one question:

> **Can an autonomous agent be both powerful AND trustworthy?**

The answer is **yes**, if its autonomy is:
- **Layered** (different zones with different controls)
- **Transparent** (fully auditable)
- **Limited** (by design, not by permission)
- **Reversible** (user can override)
- **Evolutionary** (can improve with feedback)
